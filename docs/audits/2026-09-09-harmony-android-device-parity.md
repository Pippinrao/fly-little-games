# 鸿蒙与 Android 双真机对比及补齐清单

测试日期：2026-09-09，约 23:21–23:39（北京时间）。

## 结论与测试对象

当前鸿蒙已具备游戏中心、五类设置、操控编辑器、许可页面和内置游戏运行入口；本轮两台真机均实际启动《来自下方》，通过触摸 START 进入游戏。鸿蒙仍未达到 Android 当前版本的可用性：确认了 **1 项发布阻塞问题，以及 4 组功能/界面差距**。不能根据这些抽样测试给出可信的“完成百分比”。

本轮测试的是手机中原有安装包，未重编译或替换 APK/HAP：

| 项目 | Android | 鸿蒙 |
|---|---|---|
| 真机 | V2324A | HBN-AL80 |
| 系统 | Android 16 / API 36 | 6.1.0.135(SP8C00E120R5P5) / API 24 |
| 应用包名 | com.flynes.emu | com.flynes.emu |
| 应用版本 | 0.1.0 / versionCode 1 | 1.0.0 / versionCode 1000001，debug |
| 安装包时间证据 | lastUpdateTime 2026-09-03 00:06:26 | updateTime 1788963589133 |
| 操作工具 | Mobile MCP + ADB 原始触摸事件 | HDC uitest + snapshot_display |

两机外部 ROM 数据集未做一致性校验，不能用两边游戏数量、游戏名称或封面差异证明兼容率差异。当前安装包也不等于 `codex/nearby-multiplayer` 分支；源码仅用于解释实测故障。

## 已确认补齐项

### 1. P0：来源扫描不能阻塞整个应用并导致系统杀进程

- **实测**：鸿蒙从游戏中心进入设置后出现无响应并退回桌面；后续操控编辑、游戏暂停和来源操作也遭遇退桌面，导致连续流程中断。Android 本轮设置、启动、暂停、回游戏中心流程未出现同类退出。
- **确证日志**：`harmony-custom-freeze.log` 第 20 行是 `Reason:THREAD_BLOCK_6S`；第 124–125 行主线程栈是 `scanDirectory (HarmonyRomScan.ets:44) → scanManagedRoms (GameCenter.ets:581)`。3 秒与 6 秒采样都落在同一 ZIP 扫描链中。
- **结论边界**：最早看到故障时正在操作“显示→自定义”，但不能将根因归为画质逻辑。后续每次退出均未单独取得完整故障栈，不能声称它们全部同根因；已取得的首份报告足以确认同步扫描阻塞。
- [ ] 将目录遍历、ZIP 读取/解包和 ROM 哈希移出 UI 线程。
- [ ] 为扫描补充任务去重、进度、取消和跨页面生命周期管理。
- [ ] 使用本次同一鸿蒙 ROM/ZIP 数据集，冷启动后立即切换设置、来源、游戏，连续 10 轮无 `THREAD_BLOCK_3S/6S`、卡死或退桌面；同时核验扫描结果完整。

证据：[故障报告](../../.artifacts/parity-device-20260909/harmony-custom-freeze.log)、[过滤日志](../../.artifacts/parity-device-20260909/harmony-custom-freeze-hilog.txt)。

### 2. P1：补齐可操作的自定义画质设置

- **Android 实测**：点击自定义并向下滚动，可见刷新率、帧呈现、像素重建、后处理、画面比例及保护开关。当前保留的自定义值展示过 90 Hz、需要资格验证的运动补偿/MMPX、CRT。
- **鸿蒙实测**：点击自定义后，完整浏览到显示页底部，“自定义管线”卡片内只有一个“省电”单选行；点击该行没有展开其他选项。下面直接是自适应保护和三种画面比例。
- **边界**：这证明配置界面不对齐；没有用画面或性能数据验证 Android 的高阶处理实际生效。两端极致都显示锁定，不能把锁定本身算鸿蒙缺失。
- [ ] 提供与已支持后端对应的独立刷新率、帧呈现、像素重建及后处理选项；未支持项明确禁用并解释原因。
- [ ] 验证选择→返回游戏→再次进入→重启后的持久化，并展示请求模式与实际模式。

证据：[Android 上半页](../../.artifacts/parity-device-20260909/android-custom.png)、[Android 下半页](../../.artifacts/parity-device-20260909/android-custom-spatial.png)、[鸿蒙自定义卡片](../../.artifacts/parity-device-20260909/harmony-custom-options.jpeg)、[鸿蒙显示页底部](../../.artifacts/parity-device-20260909/harmony-display-bottom.jpeg)。

### 3. P1：使 4:3 设置与实际游戏输出一致

- **实测**：两端显示页均展示 4:3 为当前比例。相同内置游戏运行截图中，Android 内容区域宽约 1680、高 1260，比例 1.333；鸿蒙内容区域宽约 1344、高 1260，比例约 1.067，呈现更窄的画面。
- **测量**：读取原始截图第 1 行的亮色连续区域，Android 范围 x=560…2239；鸿蒙 JPEG 阈值检测 x=750…2092（压缩使边缘约有 1 像素误差）。截图可直接观察上述差异。
- **边界**：切换三种比例并重启的完整回归受冻结影响，未完成；不将本轮现象外推为所有设置和所有 ROM 永远无效。
- [ ] 核对 4:3、方形像素、整数缩放从设置持久化到实际渲染区域的映射。
- [ ] 同一 ROM 分别切换三种比例，在两机截图中量出目标区域，验证返回设置和重启后保持一致。

证据：[Android 游戏](../../.artifacts/parity-device-20260909/android-playing.png)、[鸿蒙游戏](../../.artifacts/parity-device-20260909/harmony-playing.jpeg)、[鸿蒙比例选中状态](../../.artifacts/parity-device-20260909/harmony-custom-options.jpeg)。

### 4. P1：修复操控布局编辑页的底部裁切

- **实测**：两端均能进入布局编辑器。鸿蒙 2844×1260 横屏上“保存布局”的可见边界为 `[1831,1209][2777,1260]`，只露出底部屏幕中的 51 像素；“放弃”未出现在首屏。Android 同一设备方向上保存和放弃均可见。
- **边界**：尝试拖动、撤销及滚动时鸿蒙发生退出，因此**未证实按钮完全不可到达，也未验证保存功能失败**。确认项是首屏裁切；操作闭环仍待测。Android 编辑器的透明度滑条在本机也被压缩，不能把 Android 整页称为无问题基线。
- [ ] 对横屏可用高度、安全区与系统字体缩放做适配，将保存/放弃固定在可见区域或提供明确可滚动操作区。
- [ ] P0 修复后完成拖动→撤销→保存→进入游戏→重启复查，以及修改→放弃的回归。

证据：[Android 编辑器](../../.artifacts/parity-device-20260909/android-layout.png)、[鸿蒙编辑器](../../.artifacts/parity-device-20260909/harmony-layout.jpeg)、[鸿蒙节点数据](../../.artifacts/parity-device-20260909/harmony-layout.json)。

### 5. P2：补齐来源状态、数量和重新扫描入口

- **Android 实测**：来源页展示内置来源、设备目录、已就绪状态、游戏数量；外部目录具有“重新扫描”和“移除”。本机显示内置 1 个、外部 2224 个游戏。
- **鸿蒙实测**：来源页仅显示 `roms` 名称和移除，以及顶部添加游戏/添加目录按钮，没有显示该来源的数量、状态或重新扫描入口。游戏中心“全部”分类已有外部游戏，提示仍为“内置游戏已就绪 · 添加目录即可浏览自己的游戏”。
- **边界**：未删除用户来源；目录选择器尝试被退出打断，因此没有判定导入一定失效，也没有将两机游戏数量不同算作扫描漏项。
- [ ] 显示来源状态、扫描进度、成功/失败摘要和游戏数量。
- [ ] 提供重新扫描、可恢复错误的重试入口，并与后台任务去重配合。
- [ ] 游戏中心状态提示根据当前真实来源和结果更新。
- [ ] 用独立测试目录验证添加→扫描→新文件重扫→撤销授权→恢复；移除只移除授权/索引，不删除 ROM。

证据：[Android 来源](../../.artifacts/parity-device-20260909/android-sources.png)、[鸿蒙来源](../../.artifacts/parity-device-20260909/harmony-sources.jpeg)、[鸿蒙已有外部游戏的首页](../../.artifacts/parity-device-20260909/harmony-relaunch.jpeg)。

| 五类设置导航 | 两端显示/操控/音频/游戏与语言/关于均实际打开 |
| 方向模式、振动强度和预览入口 | 两端可见；未验证全部模式的实际输入和触感 |
| 音频及焦点设置入口 | 两端可见；未采集实际声音、焦点抢占或来电证据 |

| 暂停与返回游戏中心 | Android 实际打开三项暂停菜单并返回游戏中心；鸿蒙尝试后发生退出，未完成验收 |

- [ ] 暂停→继续、暂停→设置→返回、暂停→游戏中心→继续游戏；确认 START 与应用暂停分离。
- [ ] 后台恢复、正常退出自动存档、强制结束后恢复、跨 ROM 存档隔离。
- [ ] 布局编辑保存/放弃、缩放/透明度、重启持久化及大字体可用性。
- [ ] 方向模式、斜向、多点触控、松手取消、A/B 连续输入及振动实际触感。
- [ ] 来源文件/目录授权、ZIP 多条目、重新扫描、失败重试、撤销授权；采用同一校验过的数据集。
- [ ] 搜索、收藏增删、最近列表及重启持久化；本轮不以初始列表状态代替这些操作验证。
- [ ] 语言切换覆盖首页、设置、暂停与错误提示；音频开关、焦点切换和后台音频。
- [ ] 帧时间、输入延迟、音画同步、长时温控/功耗和外接手柄；本轮未测量这些指标。

## 交付与状态

原始界面节点、截图、故障日志保存在 `.artifacts/parity-device-20260909/`。本报告只将实际截图/操作/系统日志支持的现象列入确认清单。未安装新包，未删除用户 ROM 或来源，未修改产品源码。

Android 本轮将画质临时切为自定义以查看选项，随后点回原来的均衡；游戏测试推进了内置游戏并产生正常的最近/封面/自动存档变化。鸿蒙也做过自定义选择和游戏启动，但由于反复被杀，最终设置持久化状态未能再次核验；布局保存没有执行成功确认。

建议实施顺序：**先修扫描冻结 → 再完成暂停/存档/布局闭环复测 → 补自定义画质与比例 → 完善来源反馈与界面适配 → 最后做性能和长时测试**。
