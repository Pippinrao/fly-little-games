# Offline bilingual game titles

The shared offline index identifies imported games by the SHA-256 of the complete
uncompressed ROM. Renaming an archive, inner ROM, or source directory does not
change a fingerprint match. Android, HarmonyOS, and iOS consume the same generated
native table. Display language does not enter the identification or persistence key.

## Implemented behavior

`fly_game_title_resolve` and `fly_catalog_snapshot_get_title` are additive C APIs.
They return process-lifetime metadata strings and match kind 0 (unknown),
1 (fingerprint), or 2 (unique normalized alias). Existing catalog ABI structures,
canonical IDs, variant IDs, favorite/history keys, and save identities are retained.

Fingerprint matching takes precedence over aliases. Name fallback uses a ZIP's
inner ROM name, with conservative extension, separator, whitespace, case, and
explicit region-tag normalization. Different bilingual titles sharing an alias
make that alias ambiguous; such names fall back instead of guessing a series or
edition. Sequels, translations, hacks, and multicarts keep distinguishing text.

All three platform bridges copy bilingual metadata into existing presentation
models. Chinese selects the Chinese title; other locales select English, with the
other title and then the original-name fallback when necessary. Searches include
both languages and aliases. Compatibility remains independent of identification.

Android preserves explicit manual title overrides, including their existing enum
wire ordinals. The legacy library displays its stored rows immediately, backfills
missing fingerprints on a worker, and saves those hashes for later language changes.
Launch bytes are reidentified so stale legacy metadata cannot label a replacement
ROM. Running activities retain the staged ROM and bilingual title across language
recreation. Long pause titles are limited to two lines, with the complete name
available to accessibility services.
