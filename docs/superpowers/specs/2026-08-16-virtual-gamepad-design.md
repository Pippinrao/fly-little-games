# FlyNES 虚拟按键 Overlay 设计（Virtual Gamepad）

> **Status:** 已批准（用户确认 2026-08-16）
> **依据:** `docs/superpowers/specs/2026-08-15-nes-emulator-design.md`（§5 输入）、阶段 1「完整可玩」目标、用户需求"参考王者/和平精英的手游操作按钮，给模拟器加上操作按钮"。

---

## 1. 问题

当前输入方案（`TouchController.java`）是**隐形触摸区**：左半屏分区映射方向键、右半屏分区映射 A/B、长按 500ms 映射 SELECT/START。没有可见按钮、没有按压反馈、单指支持。用户反馈"没有操作按钮没法玩"，要求参考《王者荣耀》《和平精英》等手游的触控布局，加可视操作按钮。

## 2. 目标与非目标

**目标：**
- 横屏全屏下提供手游风格的虚拟按键 Overlay：左下虚拟摇杆、右下 A/B 动作键、右上 START/SELECT 功能键。
- 所有控件带按压反馈（高亮/放大），多指独立跟踪。
- 保持零依赖（纯 Android View + Canvas，无第三方库、无 XML drawable 资源），符合项目"Java 代码构建 UI"风格。
- 替换现有 TouchController，不破坏既有 ROM 加载/自动存档/音频主时钟等流程。

**非目标（YAGNI）：**
- 不做按钮位置自定义拖拽/布局保存（可扩展基座预留接口，不在本次范围）。
- 不做摇杆/十字键切换（用户已选摇杆；后续设置页可加）。
- 不引入手柄（蓝牙/OTG）——那是阶段 1.5「外部手柄」方向。
- 不改 core/C ABI（纯 app 层 UI 改动）。

## 3. 布局（横屏全屏）

```
┌────────────────────────────────────────────────┐
│ [SELECT][START]                        [⏸]     │  ← 右上功能键区
│                                                │
│            （游戏画面：256×240 缩放居中）         │
│                                                │
│    ╭────────╮            ╭──╮      ╭────╮      │
│    │  摇杆   │             A  │      │  B  │      │  ← A 在 B 左上方（B 主键更大）
│    ╰────────╯            ╰──╯      ╰────╯      │
│    （左下，底座固定）        （右下主区）         │
└────────────────────────────────────────────────┘
```

- 屏幕分左右两半：左半 = 摇杆活动区，右半 = 动作键区。
- 摇杆固定左下角；B/A 固定右下角；START/SELECT 固定右上角（靠近手机顶部，拇指不易误触，方便随时暂停）。
- 游戏画面居中显示，Overlay 覆盖其上（半透明，不遮挡画面核心区域）。

## 4. 控件规格

### 4.1 虚拟摇杆（左下，吃鸡/王者同款）

| 项 | 值 |
|---|---|
| 底座 | 固定圆盘，半径 ≈ 56dp，半透明（填充 + 描边），静止时可见（区别于"隐藏式摇杆"） |
| 帽 | 按下时出现并瞬移到手指位置；半径 ≈ 28dp，不透明 |
| 拖动 | 帽跟随手指；位移饱和于底座半径（方向全量输出） |
| 松手 | 帽回中，输出归零 |
| 方向映射 | 手指相对底座圆心的极角划分 8 扇区 → NES 方向键位：上/下/左/右及 4 个斜向（斜向 = 两键同时按下） |
| 死区 | 圆心半径 < 0.15×底座半径 视为中位（不输出方向），防误触 |
| 位移输出 | 扇区判定即可（NES 是离散方向，不需要模拟量） |

### 4.2 动作键 A/B（右下主区）

| 项 | B（主键） | A（副键） |
|---|---|---|
| 位置 | 右下角 | B 左上方 |
| 半径 | ≈ 40dp | ≈ 32dp |
| 视觉 | 半透明圆钮 + 描边 + 字母标签 | 同 |
| 反馈 | 按下高亮 + 轻微放大（1.1×） | 同 |

A/B 相对位置固定（A 在 B 的 45° 左上方，间距 ≈ 2×B 半径），符合 NES 手柄肌肉记忆：拇指根部按 B（跳跃/射击），指尖按 A。

### 4.3 功能键 START / SELECT（右上角）

- START：横条小键（宽 ≈ 56dp、高 ≈ 24dp），标签"START"，点击 → 发一次 START 脉冲（按下 50ms 释放）+ 弹出暂停菜单。
- SELECT：旁边小圆钮（半径 ≈ 18dp），标签"•"，点击 → 发一次 SELECT 脉冲（按下 50ms 释放）。
- 右上角另有"⏸"暂停按钮？——**不**。按已确认设计：START 即暂停菜单入口（见 §5.3），不再单独放 ⏸，避免角落按钮过多。右上角只放 START/SELECT 两个小键。

### 4.4 视觉风格

- 主色：白色半透明（`0x66FFFFFF` 填充 / `0xCCFFFFFF` 描边），与现有 ℹ️/📚 按钮风格一致。
- 按压态：高亮 `0xAAFFFFFF` 填充 + 放大。
- 标签：白色，`density` 缩放（`dp`），`Paint` 抗锯齿。
- 全部尺寸用 `dp`（`getResources().getDisplayMetrics().density` 换算），适配不同分辨率。

## 5. 交互逻辑

### 5.1 多指跟踪

- `onTouchEvent` 用 `MotionEvent` 的 `pointerIndex` / `pointerId` 维护 `SparseArray<PointerRole>`：每个活动指针独立判定其命中的控件（摇杆 / B / A / START / SELECT / 无）。
- 指针 DOWN 时按命中判定分配角色；MOVE 时按角色更新状态；UP/CANCEL 时释放角色并复位对应按钮。
- 支持左手摇杆 + 右手 B 同时按（这是对现有单指方案的关键升级）。

### 5.2 输入合成

- 每个控件维护自己的"当前按住"状态，汇总为 NES 按钮位掩码（与 `NesCore.setInput` 的位定义一致：A=0x01 B=0x02 SELECT=0x04 START=0x08 UP=0x10 DOWN=0x20 LEFT=0x40 RIGHT=0x80）。
- 摇杆方向（含斜向）与动作键**叠加**：例如斜上 + B = `UP|RIGHT|B`。
- 位掩码变化时通过 `Listener.onButtons(int)` 通知（沿用 `TouchController.Listener` 接口签名，MainActivity 无需改接口）。
- START/SELECT 是**脉冲**（非按住）：DOWN 时置位，50ms 后复位；脉冲期间若同时按住其他键不受影响。

### 5.3 暂停菜单

- START 点击 → 弹出 `AlertDialog`（半透明、游戏内暂停语义）：
  - **继续游戏**：发一次 START 脉冲（NES 侧恢复）+ 关闭菜单
  - **游戏库**：`startActivityForResult(GameLibraryActivity, REQ_LIBRARY)`（复用现有换游戏流程，关闭菜单）
  - **许可信息**：`startActivity(LicensesActivity)`
  - **取消**：关闭菜单（不发 START，游戏保持暂停）
- 暂停菜单弹出期间，Overlay 应忽略触摸（`dialog.show()` 自带模态阻断，天然满足；但需确保 dialog 取消时输入状态复位）。
- 游戏内按 START 暂停是 NES 游戏自身的状态（多数游戏支持 START 暂停），模拟器只负责转发脉冲；若游戏无暂停功能，菜单仍可"取消"返回继续玩。

### 5.4 生命周期

- `onPause`/`onDestroy`：复位所有按钮状态（`buttons=0` 通知 core），移除任何 pending 的 START/SELECT 复位 Runnable。
- 现有 `stopAudioThread`/自动存档流程不因 Overlay 改变。

## 6. 架构与文件改动

### 6.1 方案 A（选定）：单个自定义 View `GamepadView`

| 文件 | 动作 |
|---|---|
| `app/src/main/java/com/flynes/emu/GamepadView.java` | **新建**（≈400 行）：Canvas 绘制 + 多指触摸 + 摇杆数学 + 按钮反馈 + 位掩码合成 |
| `app/src/main/java/com/flynes/emu/MainActivity.java` | 替换 `TouchController` → `GamepadView`；移除现有 📚/ℹ️ 浮动按钮（收进暂停菜单）；接暂停菜单回调与游戏库/许可跳转 |
| `app/src/main/java/com/flynes/emu/TouchController.java` | **删除**（被替换的死代码） |

**理由：** 摇杆/按钮是一个整体交互面（多指角色分配、位掩码合成、统一绘制），拆成多个 View 会让触摸命中分发（重叠区、拦截顺序）复杂化，收益小。单 View 内聚全部输入/绘制逻辑，符合项目"零依赖、Java 代码构建 UI"风格。

### 6.2 不选方案

- **B. 多 View 叠加（每个按钮一个 View）**：触摸分发复杂、重叠区域命中不确定、状态同步繁琐。
- **C. 第三方手柄库 / Jetpack Compose**：破坏零依赖与 APK 体积目标，引入额外许可与学习成本。

## 7. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 屏幕旋转/尺寸变化 | Overlay 尺寸按 `onSizeChanged`/`onLayout` 重新计算（dp → px），不缓存失效坐标 |
| 多指同时按同一控件 | 每个指针独立角色；同一控件被第二次 DOWN 命中时，旧指针优先（忽略新指针或替换，选**忽略新指针**，防抖动） |
| 摇杆拖动超出底座 | 帽限位在底座边缘（位移饱和），方向全量输出，不丢方向 |
| dialog 关闭方式 | 点外部取消/返回键关闭时，若 START 已发脉冲且游戏未暂停，不做补偿（用户自选） |
| 低内存 | 无新增持久状态，无泄漏点（Handler/Runnable 在 onDetachedFromWindow 清理） |

## 8. 测试与验收

1. **构建**：`.\gradlew.bat assembleDebug` BUILD SUCCESSFUL。
2. **真机安装**：`adb install` 到 vivo V2324A。
3. **视觉验证**：截图确认摇杆/按钮渲染位置正确、半透明风格、按压反馈生效。
4. **功能验证（adb 注入 + 手动）**：
   - 摇杆拖动 → 8 方向各触发正确键位（含斜向 = 两键）
   - A/B 按下 → 高亮 + 对应键位；同时按摇杆方向 + B → 位掩码叠加
   - START 点击 → 弹出暂停菜单；继续/游戏库/许可三条路径各验证一次
   - 多指：左手摇杆 + 右手 B 同时操作
5. **回归**：自动存档/恢复、库切换游戏、音频 60fps 不回归（现有 5 分钟时序验收策略复跑一次简版）。
6. **提交**：`feat: add virtual gamepad overlay (joystick + A/B + START/SELECT + pause menu)`。
