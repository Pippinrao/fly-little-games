# Offline bilingual game titles

`shared/data/game_titles.json` is the reviewed, versioned metadata source. The
generated `shared/data/game_titles.inc` is shared by native platform builds. The
index contains title facts and full uncompressed ROM SHA-256 fingerprints only;
it contains no ROM bytes, archive content, private filenames with paths, or
machine-specific locations.

Run with Python 3.10 or newer, using only its standard library:

```powershell
python -m unittest discover -s tools/game_titles -p 'test_*.py'
python tools/game_titles/game_titles.py generate
python tools/game_titles/game_titles.py check
python tools/game_titles/game_titles.py verify-corpus --corpus '<private corpus directory>' --report local-data/game-titles/corpus-verification.json
```

`verify-corpus` defaults to `manifest.csv` inside the supplied corpus directory.
`--manifest` can select another manifest. The manifest columns consumed are
`output`, `sha256`, and `size`. Each output ZIP must contain exactly one ROM
member (`.nes`, `.fds`, `.unf`, or `.unif`). Every ROM is read and hashed, without
extraction, and compared with its manifest digest and size. The command fails
for unreadable archives, extra archives, missing index hashes, additional index
hashes, duplicates in manifest outputs, or changed ROM bytes. Reports belong in
ignored `local-data/`, since they may include private archive names on failures.

## Metadata and title review

Each record has:

| Field | Meaning |
| --- | --- |
| `sha256` | Lowercase SHA-256 of the complete uncompressed ROM, including its file header |
| `id` | `nes-` followed by the complete SHA-256; stable across source directories |
| `en`, `zh` | Display titles; edition details stay attached to their ROM |
| `aliases` | Other corpus titles and readable original title strings, without paths or extensions |
| `english_source` | `source_filename`, `local_crc_title`, `curated`, or `translation` |

Chinese titles start from the user's existing manifest. Duplicate archives with
the same hash collapse to one record and retain their distinct names as aliases.
English names come from readable source-member basenames, factual title matches
in the user's local `nesromdb.dat`, or individual expansions/translations.
The local title lookup used the CRC32 of the complete ROM or complete iNES
payload, never the partial PRG CRC field. Hash identity is always established by
SHA-256; CRC lookup was only a title-review aid. The database file is not bundled.
The follow-up title audit also compared complete iNES payloads after excluding
127 or 128 trailing copier bytes. This corroborated several short-name expansions
and identified Contra Force, Blades of Steel, Bomberman Collection, and Cobra
Command. Those hashes still include every original byte; only the title lookup
excluded the copier suffix.

DOS abbreviations and undecodable filenames are not accepted as English display
titles. Where an official English title could not be established, a readable
translation is explicitly marked `translation`; that field does not assert an
official localized release. Original corpus labels can contain historical naming
errors or region mislabels, so aliases retain their source spelling. Hash checks
verify coverage and byte identity, not the historical accuracy of every source
label. Filename-derived romanized titles are marked separately from curated names.

To update a title, edit the JSON record for the matching full hash, retain useful
prior names as aliases, choose the correct provenance, and regenerate. Never
deduplicate solely by title: regional releases, hacks, fan translations,
multicarts, revisions, and sequels can share a title while having different hashes.
No online service is required at runtime or to regenerate the native table.

The generator validates every record, rejects missing titles, invalid fingerprints,
duplicate hashes/aliases, unstable IDs, placeholder titles, CJK/mojibake in English
display titles, embedded control characters, and local paths. `check` also compares
the complete generated bytes, so a title edit cannot silently leave stale native
metadata. Entries are emitted in SHA-256 order with UTF-8 text and JSON-compatible
C++ string escaping. The macro contract is:

```cpp
FLYNES_GAME_TITLE("sha256", "nes-sha256", "English", "中文", "alias one\nalias two")
```

The initial corpus audit covered 2,393 archives and 2,222 unique ROMs with zero
SHA-256 or size mismatches. The source manifest SHA-256 is
`5e45a0ce727e6912ba818849631eed3f02b9ca0f368ad22dcbf946bd9dcb3856`.

The targeted bilingual review is recorded in `title-review.json`, including
before/after names, the evidence level, and credited primary references. It fixes
52 unique records: fan translations mislabeled as US releases, conflicting sequel
numbers, Chinese retitles, and misleading short filenames. Ten of those records
had contradictory region labels that the available evidence could not resolve;
their primary names omit the conflicting region claims while aliases preserve
them. This targeted audit does not certify every historical title or region in
the corpus. In particular, a local CRC title is corroboration, not authority to
override a more clearly identified same-hash source title.
