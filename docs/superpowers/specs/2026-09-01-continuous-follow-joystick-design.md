# 持续跟手浮动摇杆设计

状态：已于 2026-09-01 在对话中确认采用方案 A，等待书面规格复核。

## 背景与根因

当前移动拨杆使用固定中心与固定判定圆。触点距离中心超过约 `1.18R` 后，方向位会被清零；若触点从摇杆外或中心死区按下，输入状态也可能不接管该指针。因此，玩家划出可视范围后会“掉操作”，即使手指仍未抬起，划回来也可能无法继续。

历史提交曾实现左半区接管、动态中心和基座跟随，但最终合并时相关 `GamepadView`、命中映射和测试被另一侧版本覆盖。现有测试只覆盖从较近位置返回固定基座的场景，没有覆盖“划出数倍半径后再回来”这一真实操作路径。

## 目标

- 同一根手指从按下到抬起期间保持唯一的移动拨杆所有权。
- 手指划出摇杆可视范围时，方向保持饱和输出，不因距离过远而清零。
- 手指不抬起，划回、转向或反向时立即恢复对应方向，不需要重新按下。
- 左侧安全操作区内从中心死区或摇杆外按下，也能先以中立状态接管，随后移动即可产生方向。
- 摇杆基座和拨杆头真实跟随当前触点，让视觉反馈与输入状态一致。
- A/B、SELECT、START 等多指按键与移动拨杆可同时工作。
- 窗口安全区变化不丢失正在进行的触摸会话，并降低系统边缘手势抢占风险。

## 非目标

- 不改变十字键模式的行为。
- 不引入模拟速度；底层仍输出 NES 数字方向位。
- 不吞掉系统发出的真实 `ACTION_CANCEL`。
- 本次不增加“固定/浮动摇杆”用户配置项。
- 不修改无关画面质量、游戏逻辑或发行签名策略。

## 交互契约

### 指针归属

1. 系统按钮与 A/B、SELECT、START 的明确命中区域优先于移动区。
2. 左侧安全操作区内，第一个符合条件的指针成为唯一摇杆所有者。即使按下点处于死区，它也会以中立状态被接管。
3. 摇杆所有权从 `DOWN`/`POINTER_DOWN` 持续到对应的 `UP`/`POINTER_UP` 或真实 `ACTION_CANCEL`。触点越过原始圆、左半区边界或屏幕中线都不会自动放弃所有权。
4. 第二个左侧指针不能抢占现有摇杆所有者，但其他指针仍可操作 A/B、SELECT、START。

### 浮动中心与连续跟随

1. 获得所有权时，以按下点建立动态中心；中心需限制在考虑窗口安全区和摇杆半径后的可用范围内。
2. 触点在最大行程内时，基座不动，拨杆头跟随触点。
3. 触点超过最大行程时，拨杆头保持在最大行程，基座沿拖动方向跟随超出的距离。这样视觉拨杆始终贴近手指，并保留完整方向向量。
4. 超过任意视觉半径时，方向只做饱和处理，绝不因距离过远而变为零。
5. 仅在中心释放死区内输出中立；离开死区后按稳定的扇区映射输出上下左右及斜向组合。
6. 触点划回或反向时，使用同一会话的最新中心和向量连续计算，不要求重新进入原始固定圆。
7. 会话结束后，视觉基座立即回到配置锚点，不添加会增加输入延迟的回弹动画。

### 反馈与系统手势

- 视觉基座、拨杆头必须直接取自当前摇杆会话状态，不再绘制与实际判定脱节的固定离散位置。
- 触觉反馈只在首次进入方向扇区或方向发生变化时触发，不在每个 `MOVE` 上连续震动。
- Android 10 及以上使用有界的系统手势排除区域，覆盖空闲锚点或活动摇杆足迹；不得排除整个左半屏，以保留其余区域的系统返回手势。
- 收到真实 `ACTION_CANCEL`、窗口失焦或 View 分离时，必须清空所有方向并结束会话，避免粘键。

## 组件设计

### `JoystickSession`（或等价的纯输入状态对象）

负责保存所有者指针 ID、动态中心、拨杆头、当前向量和方向位，并提供纯函数式、可单元测试的几何更新。它维护以下不变量：

- 同时最多一个摇杆所有者；
- 拨杆头到动态中心的距离不超过最大行程；
- 超出最大行程只会移动基座并保持饱和输出；
- 不产生互相冲突的左右位或上下位。

### `GamepadInputState`

负责指针角色仲裁和聚合输出。它管理唯一摇杆所有者及独立按钮指针，允许中立的摇杆所有者留在状态中，并在几何重配置时保留活动指针与会话。

### `GamepadHitMap`

负责安全操作区、按钮优先区域、锚点和方向扇区等几何信息。方向计算不再包含“超过外圈即返回零”的截断规则。

### `GamepadView`

负责将 `MotionEvent` 按时间顺序送入输入状态、发布最终聚合按键、绘制会话状态、发出有限触觉反馈，并请求父容器不要拦截已接管的手势。

窗口 Insets 改变时只更新几何并夹紧活动中心，不得用新的 `GamepadInputState` 替换当前状态。真正的尺寸或方向重建可明确取消旧会话并发布中立状态。

## 事件数据流

### 按下

`DOWN`/`POINTER_DOWN` → 按优先级命中角色 → 首个左侧候选指针接管摇杆 → 建立动态中心与中立/方向输出 → 更新视觉与聚合按键。

### 移动

按时间顺序处理摇杆所有者的历史采样和当前采样 → 更新跟随中心、拨杆头与方向扇区 → 处理其他按钮指针当前位置 → 每个 `MotionEvent` 最终只发布一次聚合输出，方向变化时至多触发一次触觉反馈。

### 抬起或取消

对应 `UP`/`POINTER_UP` → 释放该角色并重新聚合；摇杆所有者结束时方向立即归零、视觉回锚。`ACTION_CANCEL` → 原子清空所有角色并发布中立状态。

### Insets 变化

重算安全几何 → 将活动动态中心夹紧到新范围 → 保留所有者 ID 和当前会话 → 用当前触点重新计算输出，不制造中途归零帧。

## 异常与安全约束

- 任意时刻只能存在一个摇杆所有者。
- 除“已接管但仍在中心死区”的摇杆所有者外，不保留无角色、无输出的普通指针。
- `ACTION_CANCEL`、窗口失焦和 View 分离都必须发布中立状态。
- 边缘手势排除区域必须限制在摇杆足迹附近，并在尺寸、Insets、活动中心变化后更新。
- 不依赖 View 可视圆范围判断手势是否仍然有效。

## 测试策略

实现严格按先红后绿推进，至少增加以下回归覆盖：

1. 左侧安全区的中心死区或原固定圆外按下，先接管为中立，随后移动能产生方向。
2. 同一指针拖到 `3R`、`5R` 仍保持饱和方向；不抬手划回、转向和反向均连续生效。
3. 超出行程时动态中心按超出量跟随，拨杆头始终不超过最大行程，视觉状态与输入状态一致。
4. 第二个左侧指针不能抢占；A/B 与摇杆多指并发不受影响。
5. Insets/命中图重配置保留活动所有者和方向，不出现瞬时清零。
6. 所有者 `UP`、真实 `ACTION_CANCEL`、失焦和分离均可靠清零。
7. 对随机指针序列验证唯一所有者、无相反方向位、拨杆头行程上限等不变量。
8. Android 事件测试真实派发 `DOWN → MOVE(越过旧边界) → MOVE(返回/反向) → UP`，同时验证父容器拦截请求与手势排除区域边界。

验证层级包括目标单元测试、完整 JVM 测试、Android 编译/Lint/Release 构建；真机在线时在 vivo 设备上复现同一连续手势。

## 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 按住后拖出原摇杆数倍半径 | 方向持续输出，无外圈归零帧 |
| 不抬手拖回并反向 | 立即输出新方向，无需重新按下 |
| 左侧安全区任意位置按下 | 获得唯一所有权，移动后生效 |
| 从中心死区按下 | 中立接管，离开死区后生效 |
| 活动时同时按 A/B | 移动与按钮同时保持 |
| 活动时 Insets 改变 | 所有权与方向连续，中心被安全夹紧 |
| 收到真实取消/失焦 | 所有输出立即归零，无粘键 |
| 系统边缘操作 | 摇杆足迹内降低抢占，其余区域保留系统手势 |
