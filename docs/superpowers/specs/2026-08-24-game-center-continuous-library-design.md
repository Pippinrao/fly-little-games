# FlyNES 游戏中心连续游戏库设计

## 目标

游戏中心首先回答“这是什么游戏”，不在主浏览界面展示原始文件名。中文环境以简体中文游戏名为主标题，英文名为次标题；英文环境反向显示。原始文件名仅用于搜索和变体诊断。

## 布局与滚动

- 左侧详情约占 30%，右侧游戏库约占 70%。
- 右侧列表填满状态栏以下的全部可用高度。
- 使用两行、连续横向滚动的 RecyclerView；行高由实际可用高度自动计算，列表没有竖向滚动能力。
- 卡片使用固定紧凑宽度和自适应高度，同屏尽量展示 8 个左右的游戏；不使用页码、翻页按钮、分页吸附或整页手势。
- 横向拖动超过触摸斜率后由 RecyclerView 接管，卡片点击只在一次完整轻点后触发，避免快速滑动误启动。

## 标题与元数据

- 扫描器根据文字脚本给标题候选标注语言：含 CJK 的外层名称作为中文候选，拉丁字符的内部 ROM 名作为英文候选。
- 去除扩展名和常见 ROM dump 标签后再展示标题；保留原始名称用于搜索和变体详情。
- 中文主界面不允许以文件名作为卡片副信息或左侧详情元信息。
- 无中文候选时使用受控常见标题词典；仍无法确定时显示可读英文标题，并标记为“暂无中文名”，不得把原始文件名伪装成已翻译标题。

## ROM 整理与部署

- `D:\FCgames\roms` 永远只读。
- 从审计结果中仅复制可玩的 NES payload；按完整 payload SHA-256 去重，同 hash 只保留一份。
- 地区版、汉化版、修订版只要 payload hash 不同就保留，避免误合并。
- 整理副本写入 Git 忽略的 `local-data/roms/organized/NES/`，文件名使用经过清理的中文标题；同时生成 manifest，记录来源、entry、hash、中英文标题。
- 手机目标目录先清空旧副本，再推送完整整理集；不清除应用设置、存档或内置游戏。

## 验收

- 自动化验证中文/英文标题优先级、搜索仍覆盖原始文件名、列表状态不再含分页。
- UI hierarchy 中不存在翻页按钮和页码，RecyclerView `canScrollVertically` 为 false、`canScrollHorizontally` 为 true。
- 实体机快速横滑能够连续到达首尾，横滑不启动游戏；点击卡片能更新左侧详情并启动。
- 手机目录文件数与 manifest 唯一 hash 数一致，随机抽样可启动且无崩溃/ANR。
